# Typography

Two families, both loaded from Google Fonts in `src/index.css`:

- **`font-display`** — Roboto Serif. The two largest headings and card titles.
- **`font-body`** — Work Sans. Body copy, labels, buttons, and `display/s`.

Each row below mirrors one Figma text style. Samples all render in `text-body` so
the comparison is purely typographic — colour is a separate token axis.

## Mapping Figma to Tailwind

**Figma AUTO line height maps to `leading-[normal]`,** which is the font's own
natural metric rather than a ratio.

## Which source each step follows

The Figma file and the live site (`dig-video-94863958.figma.site`) disagree, so the
authority is recorded per token.

**`display/l` follows Figma** — node `1:241`, style `text/display/l`: Roboto Serif
Bold 60px, leading 1.12, −2% tracking (`tracking-[-1.2px]`). It is the only step
with tracking and the only display step with a numeric leading. The site's `h1` is
Light 40px with no tracking; that version is deliberately not used.

**Every other step follows the site.** Two consequences:

`display/s` is Work Sans, not Roboto Serif. The site's `.h3` is Work Sans Medium
22, so the serif stops after `display/md`. The token keeps its `display` name
because that is still its role in the hierarchy, but it resolves to `font-body`.

No tracking anywhere below `display/l`. Figma specifies −2% on the remaining
display and button styles; the site declares none on headings and buttons and
`letter-spacing: 0` on body copy. `Button` and `Card` were carrying
`tracking-[-0.32px]` / `-0.28px` inline and no longer do.

## A known difference from Figma

Rendered line boxes are taller than Figma's. Figma uses AUTO line height (≈1.19×
the font size) while Tailwind's `text-base` is 1.5 and `text-sm` ≈1.43. On the
Button this shows up as 60px rendered vs 51px in Figma at the large size, and 40px
vs 32px at small. The proportions between sizes hold; the absolute heights differ.
Worth knowing before pixel-comparing a screenshot against the Figma frame.
