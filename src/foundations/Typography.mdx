# Typography

Two families, both loaded from Google Fonts in `src/index.css`:

- **`font-display`** — Roboto Serif. All four `display/*` steps.
- **`font-body`** — Work Sans. Body copy, labels and buttons.

Each row below mirrors one Figma text style. Samples all render in `text-body` so
the comparison is purely typographic — colour is a separate token axis.

## Mapping Figma to Tailwind

**Figma AUTO line height maps to `leading-[normal]`,** which is the font's own
natural metric rather than a ratio.

## Figma is the authority

This used to be recorded per token, because the Figma file and the live site
(`dig-video-94863958.figma.site`) disagreed: Figma won for `display/l` (node `1:241`
— Roboto Serif Bold 60px, leading 1.12) and for `display/md`, the site for everything
else. Figma's rework has settled it, and every step now follows the file.

Two things changed as a result.

**`display/s` is Roboto Serif, not Work Sans.** The site's `.h3` was Work Sans Medium
22, which is why the serif used to stop after `display/md` and this step resolved to
`font-body` in spite of its name. Figma moved it onto the serif, so the family pairing
is mechanical now — every `display/*` step is `font-display`, every `body/*` and
`button/*` step is `font-body`, with no exception to remember.

**Tracking is no longer `display/l`-only.** Every `display/*` and `button/*` step
carries Figma's −2%; the `body/*` steps carry none. That is new for `display/s`,
`display/xs`, `button/lg` and `button/s`, which this page previously documented as
having no tracking at all. The value rides on the `--text-*` token itself, so a step
picks it up from `text-display-s` or `text-button-lg` and there is nothing to write
inline — but note that substituting a raw `text-base` for the token silently drops it.

## A known difference from Figma

Rendered line boxes can be taller than Figma's. Figma uses AUTO line height (≈1.19×
the font size) while Tailwind's numeric `text-base` is 1.5 and `text-sm` ≈1.43. The
`--text-*` tokens set `normal` explicitly, so anything using its own type token
matches Figma — the gap only opens where a raw numeric utility stands in for one.

`Button` used to be the example: on `text-base` / `text-sm` it rendered 60px vs 51px
in Figma at the large size, and 40px vs 32px at small. It sets `text-button-lg` /
`text-button-s` now, so that discrepancy is closed. What remains on raw `text-base` is
the label text on `Checkbox` and `Radio` — which Figma's components do not bind to a
type style — and the documentation chrome on these pages.
